# Portfolio World — Blender → three.js Pipeline

A continuous 3D world with four thematic waypoints on one looping camera rail:

| # | Waypoint | Theme | Center | Anchor empty | `camera_waypoint` |
|---|----------|-------|--------|--------------|-------------------|
| 1 | Brutalist Atrium | Home / quote | `(0, 0, 0)` | `cam_wp1_home` | `home` |
| 2 | Elysian Garden | Projects (column + boat) | `(0, -50, 0)` | `cam_wp2_projects`, `cam_wp2_boat_seat` | `projects`, `projects_boat` |
| 3 | Western Desert | About (saloon + menu book) | `(0, -120, -10)` | `cam_wp3_about` | `about` |
| 4 | Metro Cavern | Contact (DT1 train) | `(0, -200, -30)` | `cam_wp4_contact`, `cam_wp4_inside_train` | `contact`, `contact_inside` |

A dark transit tunnel loops from the cavern back to the atrium plaza, so the
camera path is a **closed 680 m loop** (travel direction −Y, Z up in Blender).

---

## 1. Quickstart

Everything is generated by scripts — no manual modeling required to get a
working world. Blender 5.2 LTS:

```bash
"/c/Program Files/Blender Foundation/Blender 5.2/blender.exe" -b --factory-startup -P blender/build_world.py -- --export --previews --save-blend
```

Outputs in `blender/output/`:

| File | Purpose |
|------|---------|
| `world.glb` | The full scene for three.js / R3F (~13 MB before compression) |
| `world.blend` | Editable scene (open in Blender to refine assets) |
| `cam_path.json` | 500 uniform camera-rail samples + waypoint anchors for scroll control |
| `previews/*.png` | EEVEE validation renders from every waypoint + overviews |

Flags: `--only wp1,wp3` builds a subset, `--no-cam` skips the rail,
`--out DIR` redirects output. Module files: `lib_common.py` (toolkit),
`wp1_atrium.py`, `wp2_garden.py`, `wp3_desert.py`, `wp4_metro.py`,
`camera_rig.py`, `exporter.py`. `inspect_glb.py` prints a GLB summary
(animations, extras, cameras) without needing Blender.

Current stats: **976 meshes, ~226 k triangles, 76 materials, 6 glTF
animations** — comfortable for web after meshopt compression (§5).

## 2. Scene contract (names, properties, animations)

Everything the web app needs is machine-readable from the GLB — no hardcoded
positions in JS.

### Custom properties (glTF `extras` → three.js `object.userData`)

| Property | Where | Values / meaning |
|----------|-------|------------------|
| `camera_waypoint` | `cam_wp*` empties | `home` `projects` `projects_boat` `about` `contact` `contact_inside` |
| `path_u`, `path_frame` | `cam_wp*` empties | position of that waypoint on the camera rail (0..1 / frame 1..3600) |
| `interactive_type` | various | `link`, `page`, `banner`, `board`, `gate`, `train`, `boat`, `column`, `text`, `clock_hand` |
| `link_id` | boat seat labels, KONTAKT text | `researchgate`, `hinterstube`, `kenopsium`, `soon1`, `soon2`, `contact` |
| `page` | `WP3_MenuBook_Page_L/R` | `bio` / `resume` — target canvases for text textures |
| `texture_slot` | `WP1_Banner` | `portrait` — swap in the portrait+text texture |
| `shader` | water/falls/mist planes | `water`, `waterfall`, `mist` — replace material with custom shader |
| `billboard` | seat labels | face the camera in JS |
| `lightmap` | large static meshes | mesh has a second UV set named `Lightmap` |
| `path_role` | `Cam_Path_Curve` node | `camera_rail` (curve data itself does not export — use `cam_path.json`) |

### Animations (named glTF clips)

| Clip | Targets | Meaning |
|------|---------|---------|
| `cam_fly_through` | `Cam_Main` | full 120 s loop along the rail (30 fps, 3600 frames) |
| `banner_drop` | `WP1_Banner` (morph) | banner unrolls in front of the arch (2 s) |
| `saloon_doors_swing` | both batwing leaves | westerns-style swing impulse |
| `doors_open` / `doors_close` | all 12 platform-side DT1 leaves | 1.1 s slide; merged into one clip each via NLA track names |
| `turnstile_spin` | `WP4_Turnstile_Rotor` | one 120° click |

All rest poses are sane at frame 1 (doors closed, banner unrolled) because
every NLA strip starts at frame 2 with extrapolation `NOTHING`.

### Collections

`WP1_Atrium`, `WP2_Garden`, `WP3_Desert`, `WP4_Metro`, `CAM_Rig` — one glTF
node subtree each; cull by distance/waypoint in JS if needed.

Instanced assets (trees, cacti, cliffs, sleepers, bottles, flap cells,
stalactites, lily pads…) are linked-data duplicates (Alt+D equivalent): the
exporter emits **one glTF mesh shared by many nodes**, so three.js can
`InstancedMesh`-ify them or just enjoy the shared geometry.

## 3. Modeling instructions for the hero assets

The scripts already build stylized versions of everything. Use these notes
when refining by hand in `world.blend` — keep names and object origins, and
the export/interaction contract survives any amount of resculpting.

### 3.1 Nuremberg DT1 (WP4_Metro › `DT1_*`)

Authoritative dimensions come from your own simulator
([TrainModel.js](../src/simulator/TrainModel.js)): car length **18.575 m**,
width **2.90 m**, window band **0.93 m**, livery red `#b1271d`-family with the
off-white `#e6e8eb` stripe, roof `#68756B`, interior golden wood + dark blue
seats + gold-beige handrails.

Hand-refinement steps on top of the generated base:

1. **Nose**: the DT1 has a subtly *twisted corner* between front and side
   (see `createDT1TwistedCornerGeometry` in TrainModel.js). Select the two
   front corner edge loops, bevel (Ctrl+B, 2 segments, ~6 cm), then move the
   top corner verts ~3 cm inboard for the characteristic taper.
2. **Window band**: instead of separate glass quads, you can Inset (I) each
   window face 4 cm, extrude in −5 cm, and assign the glass material to the
   inner face — better silhouette at grazing angles. Keep pillar width ≥ 8 cm.
3. **Doors**: keep each leaf a separate object named
   `DT1_Car{n}_Door{k}_{E|W}{L|R}` with origin at the leaf center — the slide
   actions animate object location (local Y). Add the rubber lip (2 cm bar) on
   the meeting edge; assign `DT1_Door_Rubber`.
4. **Roof**: add the two roof cable ducts (10 cm half-round sweeps) and the
   whip antenna at the cab end. Shade smooth with sharp edges > 40°.
5. **Bogies**: the generated blocks + wheels are placeholders; real DT1 bogies
   read well with just: frame (bevelled box), two axle boxes per side
   (rounded boxes), a brake cylinder (horizontal cylinder). ≤ 900 tris each.
6. **Poly budget**: ≤ 25 k tris for the whole unit. Bevel only silhouette
   edges (body corners, roof line); never bevel interior panels.

### 3.2 Giant Ionic column (WP2_Garden › `WP2_Col_*`)

Generated: two-step plinth, torus base moldings, entasis-tapered shaft with
20 flutes (radial cosine displacement), echinus, two swept volute spirals with
eye bosses, abacus. Tilt lives on the parent empty `WP2_Column_Root`
(≈ 3.9°) — refine children freely, never bake the tilt into meshes.

By hand instead:

1. Shaft: cylinder (64 sides) → in edit mode select alternating vertical edge
   rings (Checker Deselect on edge rings) → Shrink/Fatten (Alt+S) −5 cm for
   flutes; add a Simple Deform (Taper ≈ −0.2) for entasis, apply.
2. Volute: Curve → Spiral (Archimedean, 2.3 turns, radius 0.95 → 0.1) in the
   XZ plane, give it a rectangular Bevel profile (0.26 × 0.84), convert to
   mesh, mirror to the second side, bridge to the echinus with a few loops.
3. The engraved paragraph is a Text object wrapped by the script
   (`L.cyl_wrap`); to redo manually: Text → set width via hard line breaks →
   Convert to Mesh → Simple Deform (Bend, 150°, axis Z) → shrinkwrap 2 cm
   above the shaft. Keep it a separate object (`WP2_Text_Projects`) so the
   web can raycast it.

### 3.3 Arched architrave text (WP1_Atrium › `WP1_Text_Quote`)

The script converts the quote to a mesh and vertex-warps it onto an arc of
radius `ARCH_R + 1.55` centered on the arch springline — letters stay upright
along the radius and read left→right for a viewer at +Y. Manual equivalent:
Text (Jost) → extrude 6 cm → Convert to Mesh → Curve modifier along a Bezier
arc in the wall plane → apply. If letters mirror, your curve runs clockwise —
flip its direction (Segments → Switch Direction).

### 3.4 Banner with drop animation (WP1_Atrium › `WP1_Banner`)

Generated as a 12×20 grid with baked noise billow and a shape key `Rolled`
(gathered at the rod). `banner_drop` keys the shape key 1→0 over 60 frames.
To re-do with real cloth: run a cloth sim pinned at the top row, pick a nice
draped frame, apply the sim as Basis, re-add a `Rolled` key by scaling all
verts to the top edge in edit mode. Keep exactly **one** shape key besides
Basis (morph target count matters on mobile). UVs are normalized 0..1 for the
portrait texture (`texture_slot: portrait`).

### 3.5 Saloon, sign, book (WP3)

Constructed detail is intentional: individual deck planks, porch posts with
caps, balusters, siding strips, false-front parapet, batwing leaves with
hinge-edge origins (swing = Z-rotation), 3-panel bar front, brass foot rail,
back-bar shelves with instanced bottles, mirror plane. The menu book has
separate page planes (`WP3_MenuBook_Page_L/R`, normalized UVs) for the
bio/resume canvas textures; the leather cover and page stacks are separate
so you can animate a page-turn later. Keep `cam_wp3_about` ~1 m in front of
and 0.7 m above the book looking straight down at it.

### 3.6 Split-flap board + clock (WP4 › `WP4_Board_*`, `WP4_Clock_*`)

The board is a housing box + 5×14 instanced flap cells (two materials, ~1/3
"lit") parented to a tilted root, plus a framed analog clock (12 instanced
ticks + 3 hands, each hand a separate object with `interactive_type:
clock_hand` so JS can spin them to the real time). To animate flaps, swap
cell materials in JS — do not model per-flap geometry.

## 4. Material & UV setup

### What the scripts bake in

* Every mesh gets a box-projected `UVMap` (≈ tiling-ready, 1 UV unit ≈ 3 m).
* Large static meshes (floors, terrain, arch wall, platform, bar) also get a
  smart-projected non-overlapping **`Lightmap`** UV set + `lightmap: 1` prop.
* Terrains, walls, cliffs and rocks carry a `Col` **vertex-color attribute**
  (exports as `COLOR_0`) with mild tint variation — enable `vertexColors` on
  those three.js materials for free large-scale breakup.
* Materials are plain Principled setups (albedo/rough/metal/emission), so the
  GLB is texture-free and tiny. Detail comes from the node recipes below,
  baked to textures (or reproduced in shader) — glTF cannot export procedural
  node graphs.

### Node recipes (build in Blender, then bake §4.1)

**Brutalist concrete** (`Brutalist_Concrete*`)
```
Noise (Scale 9, Detail 6) ──┐
Voronoi F1 (Scale 3.5) ──── MixRGB(0.35) ── ColorRamp(0.42→0.62 grey) ── Base Color
Geometry.Pointiness ── ColorRamp (crevice dirt, pos 0.35/0.55) ── multiply into Base Color
Separate XYZ(Object Z) ── Map Range(0..3 → 0.75..1.0) ── multiply (bottom weathering streaks)
Noise (Scale 40, Detail 8) ── Bump (Strength 0.08) ── Normal
Roughness: base 0.9, add ±0.08 from the large Noise
Board seams: Brick texture (scale 0.6, mortar 0.012) into Bump for shutter lines
```

**Weathered wood** (`Weathered_Wood*`, saloon planks)
```
Wave (Bands, Scale 1.2, Distortion 6, Detail 3) ── ColorRamp(#5C4630 → #8A6B47) ── Base
Noise (Scale 60, roughness) ── overlay 15 % (grain fleck)
Musgrave/Noise (Scale 0.8) ── ColorRamp hard stops ── multiply (grey sun-bleach patches)
Wave same ── Bump 0.15 ── Normal   |  Roughness 0.85 ±0.1
```

**Water** (pool, lake, trough — `shader: water`)
In Blender previews: Principled (Base #1A3D42, Rough 0.05, Alpha 0.75) +
Noise→Bump 0.05. On the web, replace by a custom shader (animated normal
scroll + fresnel + depth fade); planes are pre-subdivided (pool 8×52,
lake 24×18) for vertex displacement. Same idea for `waterfall` (scrolling
UV mask) and `mist` (soft additive disc).

**Glowing signs** (headlamps, KONTAKT, windows, light strips)
Principled with Emission Color + Strength (already set: lamps 18, KONTAKT 10,
strips 6). glTF exports `KHR_materials_emissive_strength`; on the web add
UnrealBloomPass / R3F `<EffectComposer><Bloom>` with threshold ≈ 1.0 so only
emissives bloom.

### 4.1 Baking lightmaps

1. Open `world.blend`, select a `lightmap: 1` mesh set (per waypoint).
2. New 2048² image `WP{n}_Lightmap` (32-bit float). In each material, add an
   Image Texture node pointing at it, **selected but not connected**, with a
   UV Map node set to `Lightmap`.
3. Cycles → Bake type **Diffuse (Direct+Indirect, no Color)**, margin 8 px.
4. Save as EXR (or PNG + AgX view transform for LDR), load in three.js:
   `material.lightMap = tex; material.lightMapIntensity ≈ 1;` and make sure
   the second UV set is bound (three r152+: `geometry.attributes.uv1`;
   the glTF loader wires `TEXCOORD_1` automatically when the material has a
   lightMap slot).
5. Keep the sun/lights in Blender identical to the web lighting rig, or bake
   only AO (Bake type AO) and multiply it in the shader instead.

## 5. glTF export settings

`exporter.py` already applies these (kwargs are filtered against the running
Blender's exporter, so version drift is safe):

| Setting | Value | Why |
|---------|-------|-----|
| Format | GLB | single file |
| +Y up | ✔ | three.js convention (JSON path samples stay Z-up — convert or set `scene.rotation.x = -PI/2` for raw JSON use) |
| Apply modifiers | ✖ | no modifiers exist; keeps the banner morph target alive |
| Custom Properties (extras) | ✔ | the whole interaction contract (§2) |
| Cameras | ✔ | `Cam_Main` with baked rail animation |
| Punctual lights | ✔ | sun, saloon lamps, platform lights, DT1 headlight spot |
| Animation mode | **NLA Tracks** | merges equally-named tracks → 6 clean clips |
| Shape keys (morph) | ✔ (normals off) | banner drop |
| Skinning | ✖ | no armatures |
| Attributes | ✔ | `COLOR_0` vertex tints |
| Vertex colors | **ACTIVE** | the default `MATERIAL` mode silently drops `COLOR_0` when no material references the attribute |
| Visible only | ✔ | hidden instancing sources are skipped |

Two facts worth remembering about `COLOR_0`: it is quantized to uint8, so
vertex "tints" must stay ≤ 1.0 (encode the *brightest* end of a gradient in
the material albedo and darken with vertex colors — see the grass→sand blend
in `wp2_garden.py`); and plain empties keep Blender's Z-up object semantics
through the exporter, so a "camera-style" empty's look axis lands on local
−Y in three.js — rotate its quaternion by −90° about X before using it as a
camera pose (`src/world/main.js` does this).

Manual export from the UI: File → Export → glTF 2.0 and mirror the table
(Include → Custom Properties + Cameras + Punctual Lights; Animation → NLA
Tracks; Data → Shape Keys without normals).

**Compression (already wired into the site):**

```bash
npx @gltf-transform/cli meshopt blender/output/world.glb assets/world/world.glb --level medium
```

12.9 MB → **3.4 MB**, structure fully preserved. Do **not** use
`gltf-transform optimize` here: its prune/join passes delete the empty anchor
nodes and merge the named meshes, destroying the extras/animation contract
(found out the hard way).

## 6. The shipped web experience

The live integration is vanilla three.js (matching the vendored setup the
U-Bahn simulator already uses — no build step, GitHub-Pages friendly):

| File | Role |
|------|------|
| `world.html` | page shell: importmap, splash, HUD (nav / titles / toast / hint) |
| `src/world/main.js` | renderer, loaders (meshopt), scene assembly, frame loop |
| `src/world/ScrollRig.js` | wheel/touch/drag/keys → scroll s → path u; waypoint stop poses; `cam_path.json` sampling with Z-up→Y-up conversion |
| `src/world/fx.js` | water / waterfall / mist shaders; per-zone fog, sky, exposure, light mix; light normalization |
| `src/world/interactions.js` | raycast links, crossing-triggered animations, book/banner canvas textures, real-time clock, billboards |
| `assets/world/world.glb` + `cam_path.json` | runtime assets (regenerate via §1 + compression above) |

Local preview: `node scripts/dev_server.mjs 8123` → http://localhost:8123/
(index.html *is* the world since 2026-07-22; the old homepage lives on as
`klassisch.html`, linked from the HUD). `world.html` is an identical alias.

Runtime choreography (all in `src/world/`):

* **Banner** — starts rolled; unrolls after the first scroll; rolls back up
  shortly before the camera passes the archway (morph target driven per
  frame in `interactions.js`, not via the exported clip).
* **Menu book** — real Über-mich/Lebenslauf copy on 2 spreads; keeps
  flipping as you scroll within the bar dwell zone.
* **Train ride** — `TrainRide.js` moves `DT1_Root` along the rail so the
  visitor rides inside through the loop tunnel (interior point lights are
  added in JS); at the `__exit` scroll stop the train parks at the plaza
  portal, `doors_open` plays and the end walls hide so you walk out the
  back. Stateless in scroll position — scrubbing backwards rewinds it.
* **Lanterns** — `WP4_Lantern_*` pivots sway in JS with a warm PointLight.
* **Freecam** — `F` toggles WASD/QE + drag-look (rig input suspended).

## 7. Using it from R3F instead

```jsx
import { useGLTF, useAnimations } from '@react-three/drei'

const { scene, animations, cameras } = useGLTF('/assets/world.glb')
const { actions } = useAnimations(animations, scene)

// interaction map from extras
scene.traverse((o) => {
  const u = o.userData
  if (u.camera_waypoint) anchors[u.camera_waypoint] = u.path_u
  if (u.interactive_type === 'link') linkables.push(o)      // u.link_id
  if (u.shader === 'water') o.material = waterMaterial
  if (u.billboard) billboards.push(o)
})

// scroll → camera: either scrub the baked clip…
actions.cam_fly_through.play().paused = true
actions.cam_fly_through.time = scroll01 * clipDuration
// …or drive the camera from cam_path.json samples (Z-up! convert once) and
// ease scroll01 through the waypoint path_u anchors for dwell time.

// arriving at a waypoint
actions.banner_drop?.reset().play()        // atrium
actions.doors_open?.reset().play()         // train doors
```

`link_id` targets: `researchgate` / `hinterstube` (→ hinterstube.html) /
`kenopsium` (→ kenopsium.html) / `contact` (mailto) / `soon1|soon2` (tooltip).
Menu pages + banner expect `CanvasTexture`s (bio text, resume timeline,
portrait) — their UVs are normalized 0..1.

### Known seams / limitations (by design)

* Terrain patches overlap in hidden blend bands (garden→desert at y ≈ −100);
  don't "fix" the duplicate ground there.
* The loop tunnel's exterior is visible from far aerial angles only; the
  in-path experience is enclosed. Keep the fog/fade in the web app for the
  tunnel segment (u ≈ 0.42 → 0.97) and the loop cut is invisible.
* Walls/glass are single-sided; render with `side: FrontSide` (default) and
  the interiors read correctly because opposite faces close the rooms.
* EEVEE previews look washed (AgX); three.js with `ACESFilmicToneMapping`
  at exposure ≈ 1 shows the intended saturation.
